# TypeSafe 工作流 — 双 Agent 协作与线程收尾规范

> 这份文件是**规则**，不写进度。
>
> **入口是 [`README.md`](./README.md)** —— 它按角色分流，告诉你该读哪几份。
> 一句话版：当前状态 → [`STATUS.md`](./STATUS.md)（覆盖式，开工先读）；
> 历史 → 仓库根 [`worklog.md`](../../../worklog.md)（只追加）；
> 结论与证据 → [`01-nl-shadow-command-test-results.md`](./01-nl-shadow-command-test-results.md)（改判定时修订）；
> 给 DA 的对外契约 → [`da-contract.md`](./da-contract.md)（极少改动）。

## 1. 为什么需要它

同一个仓库上有两类 Agent 在动：

- **平台开发 Agent（DA）** —— 业务功能、前端、数据库、后端主干。worklog 里 Task 2–13 是它的。
- **TypeSafe 测试/验证 Agent（TA）** —— TypeSafe 集成的配置调试、用例设计、实测、文档、问题定性。
  Task 14 是本工作流的第一条。

两边**没有共享对话上下文**：TA 的记忆只在 TA 的线程里，DA 读不到；DA 的对话 TA 也读不到。
能共享的只有仓库里的文件。所以整份规范只有一条主线：

> **凡是对另一方有影响的，必须落到文件里。没写进文件的，等于没发生。**

## 2. 文件分工

先定**读者**，再定写法 —— 每份文件只服务一种读者、只装一类内容：

| 文件 | 装什么 | 写法 | 读者 / 时机 |
|---|---|---|---|
| `README.md` | **入口**（按角色分流）+ 不随进度变的结论 | 极少改 | 任何一方，**新线程第一件事** |
| `STATUS.md` | 现在在哪、下一步做什么 | **整体覆盖** | 任何一方开工前 |
| `worklog.md` | 谁在什么时候做了什么 | **只追加** | 需要追溯时 |
| `01-...-test-results.md` | 判定、阈值标定依据、问题清单 | 修订，**结论必须带证据** | 要改判定 / 改阈值时 |
| `da-contract.md` | DA 不可改什么、改了要同步什么 | **稳定**，动了对外行为才改 | 碰端点的 DA |

四条禁止：

- **不要把「当前进度」写进 `README.md` 或 results 文档。** README 是**入口**：新线程第一个读它，
  它一旦写了进度就会变成**第二种真相**（实测发生过 —— README 写着"单测 178 条全绿""用例表三轮"，
  过了一整个 F-10 修复轮无人发现，因为大家都从 STATUS 拿现状、没人会去核对索引）。
  索引只写**不随进度变**的东西：读者分流、候选位置、判据、被撤销的建议。
- 不要在 STATUS 里只写"已完成"却不写**怎么验证**。没有复现命令的"已完成"等于没完成。
- 不要在 worklog 里写状态快照 —— 它是追加式日志，新线程要读十几条才知道现在在哪。
- **不要把同一件事在 README 和 STATUS 里各写一份。** 重复即分歧，分歧即误导。

## 4. 收尾（关闭线程前）清单

按顺序，缺一不可：

1. **跑质量门**，命令与结果**原文**写进 `STATUS.md`：
   `cd backend && npm run typecheck && npm test && npm run lint`
   没跑就写「未跑」。**不要把上一次的结果当这一次的**。
2. **提交**。工作区不留未提交改动；确实不能提交的，在 STATUS 里写清文件路径 + 为什么 + 怎么处置。
   **不要留在工作区里不说**。
3. **覆盖 `STATUS.md`**：现状一句话 / 已完成 / 未完成 / 下一步 / 阻塞。
   「下一步」必须具体到**命令或文件**，不能是"继续优化"。
4. **追加 `worklog.md`** 一条，`Agent:` 字段写自己的身份（见 §7）。
5. **改过判定就把 results 文档一起改**，并在 STATUS 里指明改了哪一节。
6. **动了对外行为（错误码 / 响应字段 / 状态码）就把 `da-contract.md` 一起改。**
   它是 DA 唯一的对外真相；只改代码不改它，DA 会按旧契约写前端。改不动就说明这次改动越界了。
7. **凭据检查**：`git status` 里不应出现 `backend/.env`；
   `grep -rn "TYPESAFE_API_KEY" backend/src/` 只应命中读 `process.env` 的那几行，不应出现字面值。
8. **不留临时脚本**。跑用例表的脚本要么进 `backend/tools/`（可复现），要么写明已删 + 判据是什么。
   `_cases.mts` 就是删了没留复现方式，见 STATUS 的未完成项第 1 条。
   **判据**：改一次阈值，另一个人能不能不问你就重跑出同一张表。不能，就是没沉淀。

### 4.1 环境受阻时怎么办（**不是"跳过"，是"换一种写法"**）

本工作流实测会周期性遇到 **Bash 安全分类器整体不可用**：非只读命令（`npm run *`、`npx`、`git`）
全部被挡，只读命令（`grep`/`sed`/`cat`）可过。**表现是"命令没跑"而不是"命令失败"**，
极易被误判成代码出问题。

这时**不能**因为跑不了门就不收尾，也**绝不能**把上一次的结果当这一次的写进 STATUS。按这个分支走：

1. 把**确切命令**交给用户，请他用行首 `!` 自己执行（输出会回到会话里）——
   见 §4.2 的粘贴纪律。
2. 写不进去的那几项（通常是第 1、2 条）在 STATUS 里**逐条列为未完成**，
   写清：什么没做 / 卡在哪 / **一条可以直接复制执行的命令**。
3. worklog 里记一笔（本工作流已遇到 5 次，属**已知环境现象**，不是本轮工作的失败）。
4. 若用户也跑不了（例如需要交互式登录），把该项留在 STATUS 的「阻塞」并**说明谁来做**。

**判断收尾是否成立的唯一问题**：下一个线程拿着 STATUS，能不能**不问任何人**就知道
"哪些是真的做完了、哪些只是没跑成"。

### 4.2 给用户贴命令的纪律

- 给用户执行时，**只给命令本体，不要把 `!` 前缀一起贴进代码块** —— shell 会把行首 `!`
  当**取反运算符**，退出码被反转。本轮踩过：一个 `EXIT=1` 的假信号差点被记为"检查器不过"。
- 用户**必须用半角 `!`**。全角 `！`（U+FF01）不会被识别成 bash 前缀，命令根本不执行，
  且消息会以普通文本到达 —— 看起来"跑了"其实没跑。
- **⚠️ 说明性文字一律写在代码块之前，代码块之后什么都不写。** 用户会**整段**粘贴你给的内容 ——
  代码块**后面**的散文也会被当成下一条命令执行。Task 20 实测：我在命令块后写了一句
  「Half-width `!`; the body contains none.」，结果 shell 报 `command not found: Half-width` /
  `command not found: the`。
  两个真实危害：① 那两行的退出码（127）**盖住了整段粘贴的退出码**，于是"这次到底成没成"从退出码上看不出来；
  ② 跟随的散文是**任意 shell 输入** —— 恰好以合法命令开头就会真的执行。
  **推论**：要粘贴的命令放在**最后**；看到 `command not found` 里出现你散文的词，
  说明它被扫进去了，**这不代表命令失败**，去读命令自身的输出。
- 结论依赖退出码时，**让输出落盘再读**（`> /tmp/x.txt 2>&1; echo "EXIT=$?"`），
  不要只凭终端回显判断。
- **实测与文档不符时以实测为准**，并当场把文档改对；**不要先按文档假设继续干活**。

## 5. 开工（新线程）清单

> **开线程的标准句 —— 用户只需要贴这一行：**
>
> ```
> 读 .ai-docs/designs/typesafe/README.md
> ```
>
> **必须带全路径。** 裸写「README.md」是无效指令：仓库里有多个同名文件（另有 `download/README.md`），
> 新线程得先搜一遍才知道是哪个 —— 那就不是"只需说一句话"了。
> 这句话对 TA / DA 通用，剩下的分流由 README 自己完成。

1. 读 [`.ai-docs/designs/typesafe/README.md`](./README.md)（**唯一入口**）——
   它按角色告诉你该读哪几份。
   - **TA** → 继续第 2 步。
   - **DA，且要碰 `command:parse` 端点 / 前端接入 / `app.ts` 注册行** → 读
     [`da-contract.md`](./da-contract.md) 就够，**不必**读 STATUS。
   - **DA，且不碰上述任何东西** → **到此为止**，回去干你的活；只要别动 §3 里「TA 主责」的文件。
2. 读 `STATUS.md`（唯一状态来源）。
3. 读 `worklog.md` 里**本 Agent 身份**的最后一条。
4. **先复现现状再动手**：把 STATUS 记的质量门命令自己跑一遍。
   文档写着"通过"不等于现在通过 —— 代码可能已经被另一方改过。
   实测与 STATUS 不一致时，**先把 STATUS 改对再干活**。
5. 只在 STATUS 的「下一步」上继续。要换方向，先把新计划写进 STATUS（另一方可能正依赖旧计划）。
6. 涉及语义判断的改动，先读 `01-...-design.md` 与 results 文档的对应小节，别凭直觉改问题措辞。

## 6. 不变量

改坏了会被测试拦下。**不要为了让测试变绿而改断言** —— 先判断是代码错了还是用例错了，
判断结果写进 STATUS。

| # | 不变量 | 守卫 |
|---|---|---|
| 1 | 模型输出**永不**直接写影子；端点只返回 `proposed`，人工确认后才走既有链路 | 路由不 import 影子写服务；`proposed` 只能是对象或 `null` |
| 2 | 澄清时 `proposed` 必须是 `null` —— 不允许"顺便给个建议值" | 单测断言 |
| 3 | 两条语义护栏（`mentions_timing` / `mentions_multiple`）必须**拦在取值解析之前** | "只消耗 1 次 API 调用"的用例；真实数据上 F1/F2/F3 各 1 次 |
| 4 | `rejected[].reason` 用 identifier、`hint` 用中文名 —— 机读字段不为文案让步 | `displayReason` 单测 |
| 5 | 路由必须是正则参数 `:action(command:parse)`；裸写会被 find-my-way 当成"静态前缀 + 名为 parse 的参数"，吞掉兄弟路由 | 路由注册用例 |
| 6 | `TYPESAFE_API_KEY` 只在 `backend/.env`，`src/` 里只准读 `process.env` | §4 第 6 条 |
| 7 | 不开 `TYPESAFE_LOG_LEVEL=debug` —— SDK 打印**未脱敏**请求体，物模型 + 用户原话会进日志 | 人工检查 |
| 8 | **上游/外部依赖的错误必须翻译成受控错误**：对外固定文案 + 稳定错误码，**不透传 `err.message`**（里面装着上游响应体，实测含出口 IP）；且**凡是对外发出的 5xx，服务端必须留下日志** —— `app.ts` 的 `IotError` 分支不打日志，所以日志只能在翻译处写 | 单测 T1/T2/T3（上游 reject → `UpstreamServiceError` 502/50003，`toResponse()` 不含上游内容，日志里有原始错误）；上游拒绝时**返回 502 是正确行为**，缺陷是"未捕获的 500 + 回显上游内容" |

## 8. 阈值与用例表的门槛规则

三条阈值（`CONFIDENCE_THRESHOLD` / `TIMING_THRESHOLD` / `MULTIPLE_THRESHOLD`）是在**本仓库真实数据**上
按实测分布标定的，不是抄文档示例值。因此：

- **改任何一条阈值，必须重跑 32 条用例表**，并把新分布写回 results 文档。
  单测只覆盖端点形态，覆盖不了真实分布。
- **重跑方式**（脚本在 §8 之前一度被删，导致这条规则只能靠文字复现 —— 现在落回仓库了）：

  ```bash
  cd backend
  npx tsx --env-file=.env tools/case-table.mts --dry-run     # 只列用例, 不打 API, 先确认脚本能跑
  npx tsx --env-file=.env tools/case-table.mts               # 实跑, 约 43 次付费调用
  npx tsx --env-file=.env tools/case-table.mts --only=A2,B3  # 改完一处只做定向复核
  ```

  它是**回归检查器**而不是打印器：会断言标志、**护栏归属**（用 service 同源阈值按 `parse()`
  的守卫顺序推导，不从 hint 文本反推）、以及三条不变量；有断言不过则退出码 1。
  护栏顺序改了但脚本没跟着改，表里的"护栏"列会**静静地说谎** —— 两边必须一起改。
- **加/改问题（Noul/Choice）同样要重跑**：多问一个问题会分走概率质量，
  实测已经见过 `target_property` 的 confidence 因为提问方式整簇移动。
- **不要为了"验证一下"就随手打真实 API**（要花钱，且依赖 `.env` 里的 key）。先用单测/夹具。
- **不改动开发库**：用例表跑在既有真实设备（`03d296fb…` / 产品 `prod-a1b2c3d4`）上，
  不新建产品、不新建测试设备。确有必要时先取得同意，并在 STATUS 里写下清理方式。

## 9. 各自的"私有指针"（真正让规范生效的机制）

仓库文件是公共信道，但**没有人会主动去读它**。所以每个 Agent 在自己的私有记忆里放一条指针 ——
新线程启动时自动加载私有记忆 → 拿到入口路径 → 读入口 → 拿到该读的东西。
**规范本身不会自动生效，这条指针才会。** 因此指针有三条纪律：

1. **指向 `README.md`，不要指向 `STATUS.md`。** 直接指 STATUS 会绕过角色分流，
   让 DA 也去读、进而以为该维护 STATUS。
2. **路径必须是全路径**：写 `.ai-docs/designs/typesafe/README.md`，不写 `README.md`。
   裸文件名不是地址 —— 仓库里有多个同名文件（另有 `download/README.md`），
   拿到指针的新线程还得先搜一遍，那"一句话开工"就落空了。
3. **必须写清"我是哪个角色、我的收尾动作是什么"**（见下）。

**TA 的指针**（措辞里必须带角色，因为它可能被 DA 读到）：

> "我是 **Test Engineer Agent (TypeSafe)**。仓库 `.ai-docs/designs/typesafe/README.md` 是入口，
> 开工先读它 → 再读 `STATUS.md`。收尾按 `00-agent-protocol.md` §4。
> **我要重写 `STATUS.md`；DA 不要写它。**"

**DA 的指针**（若 DA 也在同一仓库用 Claude Code）：

> "TypeSafe 工作流的入口是 `.ai-docs/designs/typesafe/README.md`。
> 我要碰 `command:parse` 端点时才读 `da-contract.md`；否则不必读，也**不要**改
> `STATUS.md` / `da-contract.md`（TA 主责）。"

> ⚠️ **私有记忆不保证私有。** Claude Code 的记忆是按**项目路径**存的：若 DA 在同一个仓库根
> 启动，它可能加载到**同一个** `MEMORY.md`。所以指针里**绝不能**出现
> "收尾必须整体重写 STATUS.md"这种**不带角色**的祈使句 —— DA 照做就会覆盖掉 TA 的 STATUS。
> 凡是可能被另一方读到的记忆，都把角色写在最前面。
